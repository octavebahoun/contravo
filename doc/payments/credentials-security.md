# Credentials Security and Key Encryption

This document details the security measures implemented to protect payment gateway credentials, webhook secrets, and API keys.

## AES-256-GCM Encryption Flow

GeniusPay secrets (`api_secret`, `webhook_secret`) must never be stored in plain text. We encrypt them in the application layer before database insertion.

- **Algorithm**: `aes-256-gcm`
- **Key Derivation**: Serviced by a 32-byte Key Encryption Key (KEK) defined in `PAYMENT_CREDENTIALS_KEK`.
- **IV/Nonce**: Cryptographically secure random 12 bytes generated per encryption operation.
- **Integrity Tag**: Generated by GCM to guarantee cipher text authenticity.

### Encryption Code (`lib/payments/credentials.service.ts`)
The `encryptSecret` function generates a random nonce, encrypts the raw secret, appends the GCM auth tag, and returns the binary buffers for storage.

```ts
export function encryptSecret(text: string): { encrypted: Buffer; nonce: Buffer } {
  const kek = getKek();
  const nonce = crypto.randomBytes(12);
  const cipher = crypto.createCipheriv('aes-256-gcm', kek, nonce);
  const encrypted = Buffer.concat([cipher.update(text, 'utf8'), cipher.final()]);
  const tag = cipher.getAuthTag();
  const encryptedWithTag = Buffer.concat([encrypted, tag]);
  return { encrypted: encryptedWithTag, nonce };
}
```

## Webhook Signature Verification

Webhook signatures are verified using `crypto.timingSafeEqual` to prevent timing attacks.

- Header signature is compared to the computed HMAC-SHA256 signature in constant time:
```ts
export function timingSafeVerify(signature: string, expected: string): boolean {
  try {
    const a = Buffer.from(signature, 'hex');
    const b = Buffer.from(expected, 'hex');
    if (a.length !== b.length) return false;
    return crypto.timingSafeEqual(a, b);
  } catch {
    return false;
  }
}
```

## Secret Rotation Procedure

If the server KEK or an organization's secrets are leaked, perform the following rotation procedures:

### 1. Rotating a Specific Organization's Secrets
Update the credentials via the API endpoint:
`POST /api/v1/payment-gateways/geniuspay`
This overwrites the existing row, generating a new salt/nonce and cipher text.

### 2. Rotating the Server KEK (`PAYMENT_CREDENTIALS_KEK`)
In case of a KEK leak, a migration script must be executed to decrypt credentials using the OLD KEK and re-encrypt them with the NEW KEK.

**Procedure**:
1. Keep the old KEK as `OLD_PAYMENT_CREDENTIALS_KEK` in env.
2. Load the new KEK as `PAYMENT_CREDENTIALS_KEK`.
3. Fetch all active rows in `payment_gateway_credentials`.
4. Decrypt using the old KEK, then encrypt using the new KEK.
5. Update database rows.
6. Remove `OLD_PAYMENT_CREDENTIALS_KEK` from production environment.
